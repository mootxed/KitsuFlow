# GitHub sync

## Авторизация

`DeviceFlowController` получает device/user code, показывает verification URI и опрашивает token endpoint не чаще `interval`. `slow_down` увеличивает интервал на 5 секунд. Одновременно работает только один controller. После получения токена выполняется `GET /user`; только затем токен записывается в `sessionStorage`.

## Чтение

Через `/user/installations` загружаются установки и их репозитории. Issues читаются постранично через Octokit; элементы с `pull_request` отбрасываются. Labels кешируются отдельно. При ошибке сохраняется последний кеш и показывается stale state.

## Запись и outbox

Компоненты не вызывают API. Store сначала обновляет UI/IndexedDB и добавляет операцию. Обработчик выполняет очередь последовательно; соседние ещё не начавшиеся update одной сущности объединяются.

Системная label создаётся только перед первым фактическим использованием. Существующая label с тем же именем не изменяется.

Создание Issue имеет особую защиту: перед сетевым POST операция помечается `requestStarted`. Любая неопределённая ошибка после этого переводит её в `attention`, потому что безопасного idempotency key у GitHub Issues API нет. Исходная заметка удаляется только в транзакции после успешного ответа.

401 очищает сессию и останавливает текущий проход, не удаляя очередь. 403/429 сохраняет reset time. Остальные update-операции имеют ограниченный exponential backoff.
